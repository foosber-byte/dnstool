# DnsToolWinForms

WinForms-приложение для работы с DNS-сервером Windows — то, чего нет в `dnsmgmt.msc`: записи
внутри Zone Scope в виде дерева, клиентские подсети, Query Resolution Policies, удалённое
управление другим сервером со своей аутентификацией, автообновление с GitHub.

Работает через встроенный PowerShell-модуль `DnsServer`. Автор: foosber, 2026. v2.4.0.

## Требования

- **.NET Framework 4.8** — обычно уже стоит на Windows Server 2016+.
- **Роль DNS Server** там, куда направлены операции (локально или через "Целевой
  DNS-сервер"). **RSAT: DNS Server Tools**, если приложение работает только удалённо.
- **Права администратора** нужны только для **локального** режима (см. ниже) — при отказе
  приложение само предложит перезапуск с UAC.
- **Visual Studio 2019/2022** — только для сборки из исходников.

## Права администратора — по требованию, а не всегда

Манифест — `asInvoker`: приложение стартует без UAC-запроса. Права нужны только когда
операция идёт **локально** (DNS-служба на этой же машине) — при удалённом управлении
(`-ComputerName`/`CimSession`) права проверяются на стороне целевого сервера через
Kerberos/NTLM, локальная элевация тут вообще не при чём.

Если локальная операция реально упёрлась в нехватку прав — приложение показывает окно
"Требуются права администратора" с предложением перезапуститься через UAC (`Verb="runas"`).
Показывается один раз за сессию, не спамит при повторных отказах.

## Интерфейс

- **Значки вместо текстовых кнопок** на всех 4 вкладках — свои, через GDI+ (`IconFactory.cs`).
  Действия с вводом данных (создать зону/scope/запись/подсеть/политику) открывают диалог по
  клику на "+". Фильтр остаётся обычным полем — живой поиск важнее компактности.
- **Подсказки "?"** — круглый пастельный значок с текстом во всплывающей подсказке
  (`HelpIcon.cs`) вместо постоянного серого текста.
- **Баннер** — справа в самой верхней панели окна, на всю её высоту (не отдельным блоком
  сверху и не втиснут в общую высоту элементов слева), клик открывает "О программе" (как и
  значок в футере).
- Двойной клик по записи — редактирование; правая кнопка мыши — меню
  проверить/изменить/удалить (на дереве записей — ещё и "создать папку").
- Сворачивание блока вывода без потери накопленного текста.

## Вкладка "Зоны"

`Get-DnsServerZone`, `Add-DnsServerPrimaryZone`, `Remove-DnsServerZone`. Типы при создании:
AD-домен / AD-лес / файловая (`.dns`). Метка `[AD]`/`[файл]` в списке. Полоса источника
зоны под списком (для Secondary — список мастер-серверов). Фильтр, сортировка, экспорт.

**Двойной клик по зоне** → сразу открывает её scope'ы на вкладке "Scopes и записи". Значок
перезагрузки зоны — `dnscmd /ZoneReload`, всегда локально (не учитывает целевой сервер).

## Вкладка "Scopes и записи"

**Дерево**: верхний уровень — scope'ы (подгружаются лениво, при первом выборе); внутри —
записи, сгруппированные по составным именам в папки (как в `dnsmgmt.msc`):
`admin.pro32connect` → папка `pro32connect`, элемент `admin`. Группировка — визуальная, из
уже загруженных данных; папка — только узел со своими дочерними узлами, одноуровневые
записи не превращаются в лишние ветки. Справа — содержимое текущей папки (папки сверху, как
в проводнике). Позиция границы запоминается (`RecordsTreeSplitter`).

**Добавление записи** учитывает текущую папку — запись `test` внутри `pro32connect` станет
`test.pro32connect`. `@` внутри папки = сама папка. Поля Priority/Weight/Port видны только
для SRV/MX.

**Создание "папки"**: правая кнопка на scope/папке → wildcard-запись `*` внутри нового
поддомена (`*.sales` → IP) — и настоящая запись, и способ сделать поддомен видимым как папка.

**Файловый режим** (значок с блокнотом) — обходной путь для Secondary-зон, где обычное
добавление падает с `WIN32 9611`: правка `.dns`-файла scope напрямую, всегда локально, с
бэкапом и `dnscmd /ZoneReload`. Explicit предупреждение при каждом использовании.

**Экспорт** записей в `.txt` — первой строкой пишется дата и **имя сервера**, с которого
сделана выгрузка (`DnsHelper.ComputerName`, если задан целевой сервер, иначе имя локальной
машины), чтобы файл был понятен и без контекста, откуда он взялся.

**Импорт** записей из такого файла (значок со стрелкой вверх): строки-папки (`📁 имя ПАПКА
N запис.`) распознаются и не импортируются как записи — вместо этого предлагается создать
соответствующий субдомен через wildcard (с IP на каждый, по желанию). Есть чекбокс
"Исключить @-записи". Импорт идёт в текущую выбранную папку/scope (как и обычное
добавление). Значения SRV/MX разбираются обратно из составного текста в экспорте
(`target:port (priority=..., weight=...)` / `exchange (preference=...)`); если запись из
файла уже существует в scope (по имени+типу) — спрашивает перезаписать или пропустить, с
массовым вариантом ("всё") — после него дальнейшие конфликты решаются автоматически без
повторных вопросов.

**Командлеты**: A/AAAA/CNAME/PTR/MX — типизированные (`Add-DnsServerResourceRecordA` и т.д.).
NS/TXT/SRV — только универсальный `Add-DnsServerResourceRecord -NS/-Txt/-Srv` (выделенных
командлетов нет). `@` в имени — запись в корне зоны.

**Редактирование** — пересоздание (сначала новая, потом старая, чтобы не терять данные при
сбое), кроме **CNAME**: DNS не даёт CNAME сосуществовать с другой записью под тем же именем
ни на секунду, поэтому порядок обратный (сначала удалить, потом добавить, с откатом при
неудаче). Удаление — через `-InputObject` с полным объектом записи.

**Проверка записи** — nslookup (`Resolve-DnsName`, вывод причёсан) и Ping (с `-t`,
источником `-S`, кодировкой CP866).

## Вкладка "Подсети"

`Get/Add/Remove-DnsServerClientSubnet`. Имя + CIDR.

## Вкладка "Политики"

`Get/Add/Remove-DnsServerQueryResolutionPolicy`. У результата `Get-...` подсеть лежит в
`Criteria`, scope — в `Content` (не `ClientSubnet`/`ZoneScope`, это имена параметров у
`Add-...`, не свойств у `Get-...`). Несколько подсетей через запятую (логическое ИЛИ).

## Удалённое управление другим сервером

Поле "Целевой DNS-сервер" сверху — все операции идут через `-ComputerName`, без переноса
приложения. Если проверка подключения текущей учёткой не проходит — открывается окно
аутентификации (логин/пароль), через `New-CimSession -Credential` (у командлетов `DnsServer`
своего параметра `-Credential` нет). Сессия кэшируется до смены сервера/закрытия приложения.

Транспорт — обычный WinRM: Kerberos (домен) или NTLM через `TrustedHosts` на клиенте (не
домен) — то же самое, что `Enter-PSSession`. Пароль не хешируется перед отправкой (Kerberos/
NTLM сам challenge-response, хеширование сломало бы аутентификацию), строится в памяти сразу
как `SecureString`. Подробный разбор — `SECURITY.md`.

Если клиент не в домене:
```powershell
Set-Item WSMan:\localhost\Client\TrustedHosts -Value "<сервер>" -Concatenate -Force
```

История последних 10 серверов — в `settings.ini`.

## Подтверждение удаления

Запись — обычное да/нет. Зона/scope/подсеть/политика — усиленное окно с 5-секундной
задержкой кнопки "Удалить".

## Прочее

- **Автоподгрузка** списков зон/scope при первом заходе на вкладку.
- **`changes.log`** рядом с exe — только реальные изменения и попытки аутентификации, без
  пароля.
- **Диагностика ошибок**: полное разворачивание CIM/PowerShell исключений; понятные
  сообщения вместо сырых дампов для типичных случаев — "не DNS-сервер" (`WIN32 1722`),
  "нужны права администратора" (см. выше), "WinRM не достучался" (TrustedHosts/файрвол/
  сетевой профиль).
- **Обновления**: кнопка в "О программе" тянет последний релиз с GitHub, сравнивает версию
  (`AppVersion.cs`), качает и ставит через `.bat`-скрипт (ждёт закрытия процесса через
  `tasklist`, копирует `robocopy`, перезапускает). `settings.ini`/`changes.log`/`*.dns` не
  трогает. Нужен исходящий HTTPS до `github.com`.

## Как открыть и собрать

1. Скачай папку на сервер, открой `DnsToolWinForms.csproj` в Visual Studio (2019/2022).
2. NuGet восстановится сам. Переключи на `Release`, собери (`Ctrl+Shift+B`).
3. Готовый `.exe` — в `bin\Release\net48\`. Копируется на сервер как есть, ничего
   дополнительно ставить не нужно (сборка PowerShell берётся из самой Windows).

**Антивирус ругается на exe** — ожидаемо для неподписанного exe, хостящего PowerShell:
подписать (`signtool.exe`), добавить в исключения, либо отправить как false positive.

**NuGet не находит `Microsoft.PowerShell.5.1.ReferenceAssemblies`** — в `.csproj` есть
закомментированный `HintPath`-блок на системную сборку, раскомментируй вместо
`PackageReference`.

## Структура

- `Program.cs` — точка входа. `MainForm.cs` — вся форма (разметка кодом, без .resx).
- `DnsHelper.cs` — обёртка над PowerShell: вызовы командлетов, разбор ошибок, `CimSession`
  для удалённой аутентификации, проверка элевации.
- `IconFactory.cs`/`HelpIcon.cs` — значки и подсказки (GDI+).
- `*Dialog.cs` — все диалоговые окна (создание зон/scope/записей/подсетей/политик,
  аутентификация, подтверждение удаления, проверка записи, "О программе").
- `UpdateChecker.cs` — обновления через GitHub. `FileLogger.cs` — `changes.log`.
  `AppVersion.cs` — версия приложения.
- `SECURITY.md` — разбор безопасности удалённого подключения со ссылками на код.
