# dnstool — правила работы агента

## Общение
- Общаться с пользователем на русском.

## Релизы (после каждого успешного изменения)
- После каждого успешно завершённого изменения кода предлагать пользователю:
  1. закоммитить изменения и запушить в `main`;
  2. поднять версию (`AppVersion`), создать git-тег вида `v2.9.x`;
  3. собрать и опубликовать подписанный релиз через `tools/make-release.ps1`
     (приватный ключ: `~\.dnstool\release-key-private.xml`), чтобы клиенты
     могли обновиться на месте через «Проверить обновления».
- Не пушить и не публиковать релиз без явного согласия пользователя.

## Синхронизация между машинами (дом ↔ работа)
Проект ведут два агента на двух машинах. Каналы:
- **Код** — только git (`origin/main`). Перед началом сессии: `git pull`.
- **Журнал передач** — `docs/HANDOFF.md`. В конце сессии дописать 2–4 строки:
  дата/машина, что сделано, что ждёт следующего агента. В начале сессии прочитать.
- **Приватный ключ подписи** — `Nextcloud/secure/dnstool/release-key-private.xml`
  (Nextcloud синкается на обеих машинах), рабочая копия — `~\.dnstool\release-key-private.xml`.
  При ротации ключа: обновить PublicKeyXml в `UpdateChecker.cs`, закоммитить,
  положить новый приватный ключ в Nextcloud, сделать запись в HANDOFF.md.
- **Перед любым релизом** (в т.ч. перед `dotnet publish -c Release`, который
  запускает автоподпись) проверять парность ключа:
  `powershell -File tools/check-release-key.ps1` (код 0 = можно подписывать,
  1 = ключ устарел — взять свежий из Nextcloud, НЕ подписывать).
- Секреты (приватный ключ) в git не коммитить никогда.
